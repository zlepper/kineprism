# Realistic UI validation fixture

This pair exercises the release CLI against a generated application screenshot containing cards,
charts, fine text, icons, shadows, transparency, and a dark/light boundary.

- `expected.png` was generated from scratch (`imagegen`, create mode).
- `actual.png` was generated by editing `expected.png` (`imagegen`, edit mode).
- The JSON report and annotated PNGs are committed under `output/`.

The creation prompt requested a front-on 1024×768 polished “Northstar” SaaS analytics dashboard
with a navy sidebar, light main canvas, header, three KPI cards, a revenue chart, recent activity,
restrained colors, consistent spacing, and no browser/device framing. The generator returned a
1448×1086 PNG.

The edit prompt requested the same canvas and presentation, moving the complete “New Customers”
KPI card down by 12 pixels, changing `1,842` to `1,846`, and slightly darkening its percentage while
preserving everything else. Generative editing also introduced broader layout/raster differences,
so this is intentionally a messy end-to-end and performance fixture—not the golden test for exact
movement classification.

Run:

```console
cargo run --release -p better-image-diff -- \
  examples/realistic-ui/expected.png \
  examples/realistic-ui/actual.png \
  --output-dir examples/realistic-ui/output
```

Exit code `1` is expected. In addition, the CLI integration suite derives a controlled crop from
`expected.png`, moves the complete “New Customers” card down by exactly 12 pixels, and requires a
`moved` finding with offset `(0, 12)` plus lower structural-aligned MAE. The exact five-pixel
card-shift contract is covered independently by the synthetic structural integration tests.
